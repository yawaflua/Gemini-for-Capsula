# Правила для ИИ-агентов и контрибьюторов

Проект: голосовой ассистент для колонки «Маруся». `marusya-agent` работает на
колонке, `marusya-server` держит сессию с моделью и веб-панель. Устройство
проекта описано в [README.md](README.md), здесь только правила работы с кодом.

## Абстракции

- **Интерфейсы на границах.** Железо, внешние API, модели и системные команды
  скрываются за интерфейсом, чтобы в тестах их можно было подменить. Образцы:
  `provider.Provider`/`provider.Session`, `audio.Capturer`/`audio.Player`,
  `controller.Volume`/`Media`/`Bluetooth`, `syscmd.Runner`, `wakeword.Detector`.
  Новый провайдер, устройство или сервис встраивается через такой интерфейс, а
  не через `if name == "..."` в коде, который им пользуется.
- **Расширять через маленькие интерфейсы.** Необязательные возможности
  оформляются отдельным интерфейсом и проверяются через type assertion, как
  `provider.Tuner`, `provider.TextSender`, `provider.VoiceLister`. Не стоит
  раздувать основной интерфейс методами, которые нужны не всем реализациям.
- **Сначала переиспользовать.** Перед тем как писать хелпер, поищите готовый:
  `config.Env*` для флагов из окружения, `writeJSON`/`writeError`/`readJSON`
  и `panelAPI` в сервере, `selfupdate`, `buildinfo`, `syscmd`. Дублировать
  логику нельзя, лучше вынести общее в функцию.
- **Без преждевременных абстракций.** Интерфейс вводится, когда у него есть
  вторая реализация или подмена в тесте. Не нужны слои, фабрики и обёртки «на
  будущее», а также конфигурация, которую никто не меняет.
- **Маленькие пакеты в `internal/`.** Независимая логика живёт в отдельном
  пакете с понятным именем и doc-комментарием `// Package x ...`, который
  объясняет, зачем пакет нужен. `cmd/*/main.go` только собирает зависимости
  и разбирает флаги, бизнес-логики там нет.

## Стиль Go

- Код должен проходить `gofmt`. Пишите в стиле окружающего кода: те же имена,
  та же плотность комментариев, те же идиомы.
- В каждом новом `.go` файле нужен лицензионный заголовок Apache 2.0, такой же,
  как в остальных файлах.
- Комментарии в коде пишутся на английском. Doc-комментарий есть у каждого
  экспортируемого имени и объясняет «зачем», а не пересказывает код.
- Всё, что видит пользователь (тексты панели, ошибки в API панели, фразы
  ассистента), пишется на русском.
- Ошибки оборачиваются через `fmt.Errorf("...: %w", err)`, логирование идёт
  через `*slog.Logger`, который передаётся явно.
- Настройки делаются флагом со значением по умолчанию из `MARUSYA_*`
  (`config.Env`). Новую настройку агента нужно добавить в
  `configs/agent.conf.d.example` с комментарием.

## Ограничения колонки (`marusya-agent`)

- Бинарник статический, без cgo, под linux/arm64 (`make agent`). Зависимости
  с cgo в агент не добавлять.
- Флеша почти нет, rootfs только для чтения. Агент живёт в tmpfs и при каждом
  запуске скачивается с сервера. Писать можно только в `/tmp` и в каталоги из
  конфига.
- Каждая новая зависимость в агенте увеличивает бинарник. Добавлять её можно
  только с понятной причиной, а лучше обойтись стандартной библиотекой.
- Память и CPU ограничены: никаких фоновых опросов без нужды, а горутины
  должны завершаться вместе с `context`.

## Протокол и совместимость

- Типы протокола лежат в `internal/models`. Новые поля добавляются с
  `omitempty`, а сервер должен работать с агентами, которые этих полей не
  присылают. Колонки обновляются не сразу.
- `models.ProtocolVersion` поднимается только при несовместимом изменении.
- Новая возможность агента объявляется через `Capabilities`/`Features` в
  hello. Сервер не должен предлагать модели инструмент, который колонка не
  умеет.

## Проверки перед сдачей

```bash
gofmt -l .
go vet ./...
go test -race ./...
node --check internal/server/panel/app.js
```

- Новая функциональность сдаётся вместе с тестом рядом с кодом (`*_test.go`).
  Для сервера есть хелперы вроде `newPanelEnv` и фейковых провайдеров.
- Если что-то проверить не удалось (например, на настоящей колонке), так и
  нужно написать.

## Git

- Сообщения коммитов пишутся на английском в повелительном наклонении, при
  необходимости с префиксом пакета: `openaichat: add fast path for short
  commands`.
- Трейлер `Co-Authored-By` не добавлять.
- Коммитить и пушить только по просьбе. Работа идёт в ветке `stage`, PR
  открываются в `master`.
