# Marusya × Gemini

Голосовой ассистент для умной колонки «Маруся» на базе **Gemini Live API**.
Проект состоит из двух частей на Go:

| Бинарник | Где работает | Что делает |
|---|---|---|
| `marusya-agent` | на колонке (linux/arm64, статический, без cgo) | ждёт ключевое слово, пишет речь, стримит её на сервер, проигрывает ответ, выполняет команды (громкость, плеер, Bluetooth) |
| `marusya-server` | на любом сервере/ПК | принимает поток от колонки, держит сессию Gemini Live, пересылает аудио туда и обратно, превращает function calls модели в команды для колонки |

```
 ┌──────────── колонка ────────────┐            ┌──────── сервер ────────┐          ┌─────────────┐
 │ mic ─► wakeword ─► VAD ─► agent │ ══ WS ═══► │ session ─► provider    │ ═ WS ═►  │ Gemini Live │
 │ speaker ◄────────────── agent   │ ◄═ PCM ═══ │          ◄─ audio/tool │ ◄═════   │    API      │
 │ amixer / bluetoothctl / mpv ◄── │ ◄─ command │ tools (function calls) │          └─────────────┘
 └─────────────────────────────────┘            └────────────────────────┘
```

## Как это работает

1. **Ожидание.** Агент постоянно пишет микрофон (`arecord`, 16 kHz mono) и отдаёт
   кадры детектору ключевого слова. Активация: внешний keyword-spotter, аппаратная
   кнопка (evdev) или `SIGUSR1`.
2. **Слушание.** После активации играет короткий сигнал, музыка ставится на паузу (ducking).
   Энергетический VAD ловит начало речи; только тогда агент шлёт `turn_start` и аудио
   (вместе с 300 мс pre-roll). Если речи нет, на сервер ничего не уходит.
3. **Конец фразы.** После ~0.9 с тишины уходит `turn_end`. На стороне Gemini
   автоматический VAD выключен, границы реплики задаёт устройство (`activityStart`/`activityEnd`).
4. **Ответ.** Gemini отдаёт нативную речь (24 kHz PCM), сервер стримит её на колонку,
   агент сразу проигрывает через `aplay`.
5. **Команды.** Если модель вызывает функцию (`volume_set`, `media_control`,
   `bluetooth_pair`, …), сервер шлёт колонке `command`, агент выполняет её и
   возвращает `command_result`, а сервер передаёт результат модели как function response.
6. **Продолжение диалога.** После ответа агент ещё 4 с слушает без ключевого слова
   (`-follow_up`). Сессия Gemini живёт `-idle_timeout` (по умолчанию 2 мин), поэтому
   контекст разговора сохраняется. Повторное ключевое слово во время ответа его прерывает (barge-in).

## Структура

```
cmd/
  marusya-agent/        точка входа агента (флаги, сборка зависимостей)
  marusya-server/       точка входа сервера
internal/
  models/               модели: протокол, аудиоформаты, команды и их результаты
  transport/            WebSocket-транспорт (общий для обеих сторон)
  provider/             интерфейс Provider/Session для realtime-модели
    gemini/             реализация на Gemini Live API (google.golang.org/genai)
    echo/               loopback-провайдер для отладки без квоты
  tools/                описание функций, доступных модели (не зависит от провайдера)
  server/               HTTP/WS-сервер и мост устройство ⇄ провайдер
  agent/                машина состояний устройства (idle → listening → thinking → speaking)
  audio/                интерфейсы Capturer/Player/Stream, PCM-утилиты, earcons
    alsa/               реализация через arecord/aplay
  vad/                  энергетический VAD и эндпоинтер фраз
  wakeword/             интерфейс Detector и Multi
    exec/               внешний keyword-spotter (stdin PCM → stdout строки)
    button/             аппаратная кнопка через /dev/input/eventN
    signal/             активация по SIGUSR1
  indicator/            интерфейс индикатора состояния (+ Multi)
    ringled/            LED-кольцо через утилиту прошивки ringled
    face/               мордашка на 7-сегментном экране (порт mordy)
  display/seg7/         драйвер 7-сегментной панели (line-display sysfs)
  sensor/light/         датчик освещённости (IIO)
  touchkeys/            сенсорная панель: громкость, mute, next, центр = активация
  evdev/                чтение клавиш из /dev/input/eventN
  controller/           интерфейсы Volume/Media/Bluetooth и Dispatcher команд
    amixer/             громкость через ALSA amixer
    bluez/              Bluetooth через bluetoothctl (или вендорский bt-pair)
    mpv/                плеер через mpv JSON IPC
    playerctl/          плеер через MPRIS/playerctl (spotifyd)
    stream/             звук YouTube и радио, который декодирует сервер
  media/                поиск и стриминг звука: интерфейс Source, HTTP-клиент колонки
    ytdlp/              реализация через yt-dlp + ffmpeg (на сервере)
  syscmd/               запуск системных утилит (с подменой в тестах)
  config/, logging/     общие хелперы для main
deploy/                 Dockerfile, docker-compose, OpenRC-сервис для колонки
configs/                примеры конфигов (server.env, /etc/conf.d/marusya-agent)
scripts/wakeword/       пример keyword-spotter на openWakeWord
```

Чтобы заменить бэкенд, достаточно реализовать нужный интерфейс:
`provider.Provider` (другая LLM), `audio.Player`/`audio.Capturer` (другой звук),
`wakeword.Detector`, `controller.Volume|Media|Bluetooth`.

## Сборка

```bash
make all
```

Получатся `bin/marusya-agent-linux-arm64` и `bin/marusya-server`. Проверить архитектуру
колонки можно командой `uname -m`: `aarch64` значит arm64, `armv7l` значит 32-битный ARM.
Для второго случая:

```bash
make agent AGENT_ARCH=arm
```

Тесты (включая сквозной: агент → сервер → echo-провайдер):

```bash
make test
```

## Запуск сервера

```bash
cp configs/server.env.example configs/server.env   # вписать GEMINI_API_KEY и токен
set -a; . configs/server.env; set +a
./bin/marusya-server -listen :8080
```

### Docker

Образ содержит сервер и агент для колонки (`/v1/agent/arm64`). Колонка скачивает агент
с этого сервера при каждой загрузке. Собирается под архитектуру хоста (amd64 или arm64).

```bash
cp configs/server.env.example configs/server.env   # ключи, токен, место
docker compose -f deploy/server/docker-compose.yaml up -d --build
docker compose -f deploy/server/docker-compose.yaml logs -f
```

Затем на колонке поменяйте `MARUSYA_SERVER` в `/etc/conf.d/marusya-agent` на
`ws://<сервер>:8080/v1/stream`. Если сервер доступен из интернета, поставьте перед ним
reverse proxy с TLS (wss://) и задайте длинный `MARUSYA_AUTH_TOKEN`.

### Веб-панель

Задайте пароль в `configs/server.env` и перезапустите контейнер:

```bash
MARUSYA_PANEL_PASSWORD=придумайте-пароль
```

Панель откроется по адресу `http://<сервер>:8080/panel/`. Без пароля она выключена. В панели есть:

- **Колонки**: какие колонки подключены, с какого IP, слушают или думают ли они сейчас.
  Там же пульт: громкость, музыка (пауза, следующий трек, поток по ссылке), ночник
  и Bluetooth. Ещё можно задать вопрос текстом: Маруся ответит голосом из колонки.
  «Забыть разговор» сбрасывает контекст диалога.
- **История**: что услышала колонка, что ответила Маруся, какие команды и навыки
  вызывались, подключения и ошибки. Лента обновляется вживую и хранит последние 500
  событий в памяти, поэтому после перезапуска сервера она очищается.
- **Настройки**: системный промпт, город и часовой пояс по умолчанию, язык, голос
  и модель. Колонки, которые сейчас молчат, получают их сразу, а занятые разговором
  получат со следующим вопросом. В Docker настройки сохраняются в томе `marusya-data`
  (`MARUSYA_SETTINGS_FILE=/data/settings.json`) и важнее значений из `server.env`.
  Кнопка «Вернуть как при запуске» удаляет сохранённые изменения.

Чтобы задавать вопросы текстом, нужен агент с поддержкой `remote_turn`. Колонка
скачивает агент с сервера при загрузке, так что после обновления сервера её достаточно
перезагрузить. Провайдер `echo` текстовые вопросы не принимает.

Пароль от панели передаётся открытым текстом, поэтому из интернета открывайте её только
через reverse proxy с HTTPS.

Основные флаги: `-gemini_model`, `-gemini_voice` (Kore, Puck, Charon, Aoede, …),
`-google_search`, `-system_prompt_file`, `-idle_timeout`, `-vertex -gcp_project …`
(Vertex AI вместо Developer API), `-provider echo` (отладка без Gemini).

Навыки на стороне сервера (флаг `-skills`, включены по умолчанию) работают без ключей,
через [Open-Meteo](https://open-meteo.com):

- `time_now`: «сколько время» → «21:05 в Ашдоде». Можно спросить и про другой город.
- `weather_forecast`: текущая погода и прогноз до 7 дней.

Всё остальное (новости, курсы, факты) модель ищет через Google Search (`-google_search`).
Местоположение колонки задаётся на колонке (`MARUSYA_LOCATION`, `MARUSYA_TIMEZONE` в
`/etc/conf.d/marusya-agent`) или по умолчанию на сервере: `-default_location Ашдод`
(часовой пояс по умолчанию берётся с ПК).

### Несколько колонок: свой регион, языки и токен

Если колонки стоят у разных людей, каждой можно задать профиль: вкладка «Колонки» →
выбрать колонку → «Профиль колонки». В профиле есть название, город (для погоды и
времени), часовой пояс, язык речи и дополнительные языки (подсказки распознаванию,
например `he-IL, en-US`). Пустое поле берётся из общих настроек. Профиль важнее того,
что колонка сообщает о себе сама (`MARUSYA_LOCATION`, `-language`), и применяется сразу,
даже к колонке, которая сейчас на связи.

Профили хранятся по ID колонки (`-device_id` агента, по умолчанию hostname) в файле
`MARUSYA_PROFILES_FILE`, в Docker это `/data/devices.json`. Тот же API есть без панели:
`GET/PUT/DELETE /panel/api/profiles/<id>`.

**Свой токен.** «Новый токен» создаёт для колонки отдельный токен. Пропишите его на
колонке в `MARUSYA_AUTH_TOKEN` (`/etc/conf.d/marusya-agent`) вместо общего. С этим токеном
колонка входит только под своим ID: проданная колонка не сможет выдать себя за чужую, а
забрать у неё доступ можно, удалив токен или выпустив новый (она сразу отключится).
Общий токен сервера (`-auth_token`) продолжает работать для колонок без своего токена.

### Будильники и таймеры

«Разбуди меня в 7:30», «будильник по будням на 7 на громкости 90», «разбуди под Кино»,
«поставь таймер на 10 минут», «какие у меня будильники», «удали будильник на 7:30».
Будильники хранит сервер (`MARUSYA_ALARMS_FILE`, в Docker `/data/alarms.json`), считает
время звонков по часовому поясу колонки (профиль или общие настройки) и заранее отправляет
колонке звонки на 8 дней вперёд. Колонка звонит сама, даже если сервер в этот момент
недоступен. «По будням» в Израиле — с воскресенья по четверг.

Звонок: нарастающий писк или музыка с YouTube, если её заказали, на заданной громкости
(потом громкость возвращается). Выключить звонок: нажать на колонку или сказать
«Маруся» — это только выключает будильник и не начинает разговор. Без реакции звонок
сам замолкает через 10 минут. Будильники видно и можно добавить в панели, в карточке
колонки.

### YouTube и радио

«Маруся, включи Кино — Группа крови», «поставь лоу-фай», «включи видео про котов с ютуба»:
модель вызывает `media_play_search`, сервер находит видео на YouTube через
[yt-dlp](https://github.com/yt-dlp/yt-dlp), ffmpeg декодирует звук, и колонка получает
готовый PCM (48 kHz mono) по HTTP (`GET /v1/media?q=…` или `?url=…`, с токеном колонки).
Ссылки (YouTube, другие сайты, интернет-радио) включаются через `media_play_url`, их можно
вставить и в панели, в поле под кнопками музыки. Туда же можно написать название песни.

На колонке ничего ставить не нужно. Пауза, «продолжи» и «стоп» работают как обычно,
на время разговора с Марусей звук останавливается, а новый трек начинается после её ответа.
Ссылки `spotify:` и «следующий трек» по-прежнему идут в spotifyd.

В Docker-образе уже есть yt-dlp, ffmpeg и Node.js. Без Docker поставьте `yt-dlp` и
`ffmpeg` на сервер: если их нет, сервер пишет в лог `media playback disabled`.
Флаги: `-media=false` выключает функцию, `-ytdlp_args` (`MARUSYA_YTDLP_ARGS`) передаёт
yt-dlp дополнительные аргументы, например `--js-runtimes node` (в образе по умолчанию) или
`--cookies /data/cookies.txt`, если YouTube просит подтвердить, что вы не бот.
YouTube часто меняется: если поиск перестал работать, пересоберите образ, чтобы
скачался свежий yt-dlp. На колонке функцию выключает `-server_streams=false`.

### Claude вместо Gemini

`-provider claude` отвечает через Claude (по умолчанию `claude-haiku-5-5`, флаг
`-claude_model`). Claude работает только с текстом, поэтому ход устроен так:
распознавание речи через Gemini (`-stt_model`), ответ Claude с вызовом функций колонки,
навыками сервера и поиском в интернете (Claude web search, флаг `-google_search`),
озвучка через Gemini TTS (`-tts_model`, голос `-gemini_voice`) по предложениям, ещё во время
генерации. Нужны оба ключа: `ANTHROPIC_API_KEY` и `GEMINI_API_KEY`.
`-claude_effort low` (по умолчанию) даёт самые быстрые ответы. В этом режиме конец фразы
определяет колонка.

```bash
ANTHROPIC_API_KEY=... GEMINI_API_KEY=... ./bin/marusya-server -provider claude \
    -auth_token secret -agent_dir bin -default_location Ашдод
```

Конец фразы определяет Gemini (`-vad server`, по умолчанию): он надёжнее работает в шумной
комнате. Энергетический детектор колонки остаётся запасным вариантом. `-vad device`
возвращает старое поведение.
Для работы через интернет используйте `-tls_cert/-tls_key` (wss://) или reverse proxy.

## Запуск на колонке (Alpine Linux)

Нужен root по ssh. Агент — статический бинарник, поэтому musl ему не мешает. Зависимости ставятся из apk
(`mpv` лежит в репозитории `community`):

```bash
make device-deps DEVICE=root@<ip-колонки>    # apk add alsa-utils bluez mpv
make deploy-agent DEVICE=root@<ip-колонки>   # бинарник, OpenRC-сервис, rc-update add
```

Настройки лежат в `/etc/conf.d/marusya-agent` на колонке; шаблон — в
[configs/agent.conf.d.example](configs/agent.conf.d.example), при первом деплое он копируется сам.
Управление сервисом:

```bash
rc-service marusya-agent restart
rc-service marusya-agent wake      # тестовая активация без ключевого слова (SIGUSR1)
tail -f /var/log/marusya-agent.log
```

### Экран, кнопки, кольцо (VK Капсула Мини)

Агент сам управляет экраном и сенсорной панелью, поэтому сервис `mordy` нужно выключить
(`rc-service mordy stop; rc-update del mordy`), иначе оба процесса будут рисовать на экране.

| Кнопка | Действие |
|---|---|
| центр, коротко | активировать ассистента; повторное нажатие, пока колонка слушает, отменяет вопрос |
| центр, удержание 1.5 с | `bt-pair` (режим Bluetooth-колонки) |
| VOL+ / VOL− | громкость ±5%, удержание — автоповтор, значение на экране |
| PROG1 | следующий трек (`playerctl`, spotifyd) |
| MICMUTE | выключить микрофон: агент получает тишину, мордашка «закрывает глаза» |

Закончить разговор можно и голосом: на «пока», «хватит», «отстань» и грубости модель
вызывает `conversation_end`. Колонка коротко прощается, не ждёт продолжения, а сервер
забывает контекст, так что следующий вопрос начинается с чистого листа.

Кольцо (по приоритету): слушает — синее, думает — фиолетовое, отвечает — зелёное,
ошибка/нет связи — красное; микрофон выключен — красное; «включи ночник» — жёлтое
(можно попросить другой цвет/яркость); иначе выключено.

Датчик света (`bh1730`, IIO) приглушает экран и в темноте укладывает мордашку спать.

Мордашка: в ожидании моргает и смотрит по сторонам (глаза `0 . 0`, при взгляде вбок
сдвигаются `00. ` / ` .00`), слушает — большие глаза, думает — глаза бегают,
отвечает — довольные `∩ . ∩`, ошибка — грустная, нет связи — грустная и засыпает.

### Bluetooth-колонка (`bt-pair`)

Если на колонке есть `bt-pair` (режим сопряжения, после которого Капсулу можно использовать
как Bluetooth-колонку), агент находит его в PATH сам (`-bt_pair_command auto`, значение по умолчанию).
На фразу «включи блютуз» или «хочу подключить телефон» Gemini вызывает `bluetooth_pair`, и агент запускает `bt-pair`.
Агент не убивает `bt-pair` по таймауту: утилита сама решает, сколько держать режим колонки.
Повторный вызов, пока она работает, ничего не делает. Если `bt-pair` нет, используется встроенный
сценарий через `bluetoothctl` (агент NoInputNoOutput, discoverable на `timeout_seconds`).

Полезные флаги агента:

| Флаг | Назначение |
|---|---|
| `-capture_device`, `-playback_device` | ALSA-устройства. Массив микрофонов часто многоканальный: заведите `plug`/`dsnoop` в `asound.conf` с понижением до mono 16 kHz |
| `-wake_command` | keyword-spotter: читает PCM из stdin, на каждое срабатывание печатает строку |
| `-button_device`, `-button_code` | кнопка активации (evdev) |
| `-mixer_control` | ALSA-контрол громкости (`Master`, `PCM`, `Speaker`…, см. `amixer scontrols`); пустое значение отключает управление громкостью |
| `-bt_pair_command` | утилита сопряжения: `auto` (по умолчанию) — `bt-pair`, если он есть в PATH; можно указать `bt-pair {timeout}`; пустая строка — встроенный сценарий через `bluetoothctl` |
| `-mpv_socket` | сокет mpv; пустое значение отключает управление музыкой |
| `-vad_threshold_db`, `-vad_silence` | чувствительность VAD и длина паузы, завершающей фразу |
| `-ringled`, `-ringled_brightness` | LED-кольцо (`auto` — `ringled` из PATH, пустое значение отключает). Слушает — синяя вспышка волной от кнопки мута, думает — фиолетовая «комета» крутится по кольцу, отвечает — зелёное дыхание, ошибка — два красных мигания, нет связи — тусклый красный. Мут — красный растекается от кнопки MICMUTE на всё кольцо и уходит обратно в неё; громкость — белая дуга на полторы секунды |
| `-ring_driver` | `spi` — кадры прямо в `/dev/spidev0.0` (плавные анимации, 30 к/с), `ringled` — один запуск утилиты на кадр, `auto` (по умолчанию) — `spi`, если доступен |
| `-ring_demo` | показать все анимации кольца по очереди и выйти (остановите сервис перед запуском) |
| `-follow_up`, `-duck_media`, `-earcons` | поведение диалога |

### Ключевое слово

Есть два способа: распознавание на сервере (слово меняется в веб-панели) и модель на самой колонке.

**На сервере.** Пока колонка ждёт, она шлёт звук с микрофона на сервер, а сервер передаёт его
в сервис `marusya-wake` (`deploy/wake`). Услышав слово, сервис будит колонку.

```bash
# configs/server.env
MARUSYA_WAKE_URL=ws://marusya-wake:2700
MARUSYA_WAKE_WORDS=антон, אנטון   # слова по умолчанию; меняются в панели → Настройки

cd deploy/server && docker compose --profile wake up -d --build
```

- **Русские слова** распознаёт Vosk (small-ru, модель уже в образе). Он работает с грамматикой
  из ключевых слов и срабатывает примерно через полсекунды после слова. Если слова нет в словаре
  Vosk, его распознаёт Whisper.
- **Иврит** и другая не кириллица идут через faster-whisper (`WHISPER_MODEL`, по умолчанию `small`,
  ~500 МБ скачиваются в volume при первом запуске). Whisper расшифровывает короткие фразы
  и сравнивает их со словом нечётко: огласовки и конечные буквы не важны, похожие на слух буквы
  (א/ע, ט/ת, כ/ק) считаются одинаковыми. На CPU это 1–3 секунды задержки, поэтому лучше
  сделать паузу после слова: «אנטון… מה מזג האוויר?». Модель `base` быстрее, но имена путает.
- Можно задать до 10 слов через запятую. Панель предупредит, если слово не поддерживается.
- Кнопка и `-wake_command` на колонке продолжают работать. Без `MARUSYA_WAKE_URL`, а также
  со старым агентом звук в режиме ожидания никуда не отправляется.

> Важно: при серверном слове микрофон слушает постоянно, и звук уходит на ваш сервер
> в локальной сети. Дальше сервера он не идёт: в Gemini попадает только запрос после
> срабатывания. Кнопка MICMUTE останавливает отправку.

**На колонке** (оставлено на будущее). В чистом Go нет готового движка распознавания ключевых
слов, поэтому агент работает с ним через простой контракт `-wake_command`: внешний процесс
получает сырой PCM в stdin и печатает строку при срабатывании. Подойдёт openWakeWord
с обученной моделью «Антон» (пример в `scripts/wakeword/`), Porcupine, microWakeWord,
Vosk с грамматикой из одного слова или штатный детектор прошивки, если его удастся так обернуть.

## Интеграции

### Объявления и вопросы через колонку (`POST /v1/ask`)

Любая программа может заговорить через колонку и, если нужно, дождаться ответа голосом:

```bash
curl -s http://192.168.31.80:8080/v1/ask -H "Authorization: Bearer $MARUSYA_AUTH_TOKEN" \
  -d '{"text": "Закрыть шторы?", "listen": true, "timeout": 120}'
# {"device":"vk-mini-a113x","answered":true,"answer":"да, закрой"}
```

Как это происходит:
1. Сервер синтезирует текст голосом Gemini (нужен `GEMINI_API_KEY`, Vertex AI не подойдёт).
2. Если колонка занята разговором, сервер ждёт, пока она освободится.
3. Колонка играет звонок, кольцо пульсирует оранжевым, текст зачитывается.
4. С `listen` колонка 10 секунд ждёт ответа. Ответ распознаётся и возвращается в JSON. Модели он не передаётся, Маруся сама ничего не отвечает.
5. Если нажать кнопку во время чтения, колонка перестанет читать и сразу начнёт слушать.

Если никто не ответил, придёт `"answered": false`. Поля запроса:
- `text` — что сказать, до 1000 символов;
- `listen` — ждать ли ответа;
- `device` — ID колонки (по умолчанию первая);
- `timeout` — сколько ждать, в секундах (по умолчанию 120, максимум 600);
- `source` — кто спрашивает, для истории в панели.

Нужен агент с поддержкой объявлений: перезагрузите колонку после обновления сервера.

Текст озвучивает Live-модель (`-gemini_model`): её просят прочитать его дословно, и тратится
квота Live API, а не TTS (на бесплатном тарифе у TTS всего 10 запросов в день).
`-ask_tts tts` (`MARUSYA_ASK_TTS`) возвращает озвучку через `-tts_model`.

### Claude Code: вопросы и ответы голосом

`marusya-ask` — хук для Claude Code (и вкладки Code в Claude Desktop):
- Claude закончил работу и задал вопрос — колонка зачитывает его: «Клод в проекте X спрашивает: …».
- Вы отвечаете голосом — Claude продолжает с вашим ответом. Технически хук `Stop` возвращает `decision: block`.
- Если промолчать, Claude останавливается как обычно, и ответить можно с клавиатуры.
- Нужно разрешение на команду — колонка об этом скажет. Подтверждать по-прежнему нужно на компьютере.
- Claude задаёт вопрос диалогом с вариантами — колонка читает вопрос и варианты. Ответ голосом закрывает диалог, и Claude продолжает с ним. Если промолчать, диалог остаётся на экране.

```bash
go install ./cmd/marusya-ask     # → ~/go/bin/marusya-ask
marusya-ask -server http://192.168.31.80:8080 -token "$MARUSYA_AUTH_TOKEN" -listen "Проверка связи?"
```

`~/.claude/settings.json`:

```json
{
  "env": {
    "MARUSYA_URL": "http://192.168.31.80:8080",
    "MARUSYA_AUTH_TOKEN": "токен из configs/server.env"
  },
  "hooks": {
    "Stop": [
      { "hooks": [{ "type": "command", "command": "$HOME/go/bin/marusya-ask hook", "timeout": 600 }] }
    ],
    "PreToolUse": [
      { "matcher": "AskUserQuestion", "hooks": [{ "type": "command", "command": "$HOME/go/bin/marusya-ask hook", "timeout": 600 }] }
    ],
    "Notification": [
      { "matcher": "permission_prompt", "hooks": [{ "type": "command", "command": "$HOME/go/bin/marusya-ask hook" }] }
    ]
  }
}
```

Что колонка зачитывает:
- если в конце ответа Claude есть вопросы — последние из них, до 300 символов;
- если вопросов нет — «закончил:» и первую фразу. Чтобы в этом случае колонка молчала, добавьте `-on_done=false`.

Код, ссылки и markdown выбрасываются. Ответ передаётся Claude как распознанная речь, с пометкой, что возможны ошибки распознавания.

### Spotify

Если Spotify настроен, музыка по умолчанию идёт из него: «Маруся, включи Кино — Группа
крови», «поставь альбом Nevermind». Модель вызывает серверный навык `spotify_play`. Сервер
ищет музыку в каталоге Spotify и отправляет колонке ссылку `spotify:…`, а агент открывает
её в spotifyd через MPRIS. Если в Spotify такого нет или spotifyd не отвечает, то же самое
само включается с YouTube. Видео, подкасты и «включи с ютуба» по-прежнему идут в YouTube.
Пауза, «дальше» и пауза на время разговора работают как раньше.

Сервер ищет от имени приложения (client credentials), без аккаунтов пользователей,
поэтому одного приложения хватает на любое число колонок. Играет колонка с того
аккаунта, в который залогинен её spotifyd. Нужен Premium.

**На сервере** создайте приложение на
[developer.spotify.com](https://developer.spotify.com/dashboard) (Web API) и задайте
в `configs/server.env`:

```
MARUSYA_SPOTIFY_CLIENT_ID=…
MARUSYA_SPOTIFY_CLIENT_SECRET=…
```

**На колонке** нужен spotifyd 0.4+ с MPRIS (`apk add spotifyd playerctl dbus`). Графической
сессии там нет, поэтому spotifyd работает на системной шине D-Bus. `/etc/spotifyd.conf`:

```toml
[global]
device_name = "Marusya"
backend = "alsa"
device = "default"          # через asound.conf, вместе с эквалайзером
use_mpris = true
dbus_type = "system"
cache_path = "/var/cache/spotifyd"   # здесь сохраняется вход
```

Разрешение для spotifyd на системной шине, `/etc/dbus-1/system.d/spotifyd.conf`:

```xml
<!DOCTYPE busconfig PUBLIC "-//freedesktop//DTD D-BUS Bus Configuration 1.0//EN"
 "http://www.freedesktop.org/standards/dbus/1.0/busconfig.dtd">
<busconfig>
  <policy user="root">
    <allow own_prefix="org.mpris.MediaPlayer2.spotifyd"/>
    <allow own_prefix="rs.spotifyd"/>
  </policy>
  <policy context="default">
    <allow send_destination_prefix="org.mpris.MediaPlayer2.spotifyd"/>
    <allow send_destination_prefix="rs.spotifyd"/>
  </policy>
</busconfig>
```

Войти один раз: `spotifyd authenticate` или выбрать «Marusya» в приложении Spotify в той
же сети Wi-Fi. Вход сохраняется в `cache_path`, после перезагрузки spotifyd логинится сам.
Сервис: скопируйте `deploy/agent/spotifyd.openrc` в `/etc/init.d/spotifyd`, затем
`rc-update add dbus default && rc-update add spotifyd default`.

spotifyd 0.4 показывает плеер MPRIS, только пока он активное устройство Spotify Connect.
Поэтому агент перед открытием ссылки `spotify:` сам делает его активным
(`rs.spotifyd.Controls.TransferPlayback`), и выбирать колонку в приложении не нужно.

Ищутся только публичные плейлисты: личные плейлисты пользователя серверу не видны.

### Home Assistant

**Маруся управляет домом.** Задайте в `configs/server.env`:

```
MARUSYA_HA_URL=http://homeassistant.local:8123
MARUSYA_HA_TOKEN=<долгосрочный токен: профиль → Безопасность>
```

Модель получает навыки `home_find` (найти устройства и узнать их состояние) и `home_control` (управлять ими). Примеры фраз:
- «включи свет на кухне»;
- «яркость в спальне на 30»;
- «какая температура в детской»;
- «закрой шторы», «запусти сцену кино».

По умолчанию голосом можно управлять светом, розетками, вентиляторами, шторами, климатом, плеерами, сценами, скриптами, `input_boolean`, пылесосами, увлажнителями и кнопками. Датчики только читаются. Замки и сигнализация недоступны, иначе дверь сможет открыть любой, кто стоит рядом с колонкой. Список меняется через `MARUSYA_HA_DOMAINS=light,switch,lock`.

**Home Assistant говорит через Марусю** — через тот же `/v1/ask`. Добавьте в `configuration.yaml`:

```yaml
rest_command:
  marusya_say:
    url: http://192.168.31.80:8080/v1/ask
    method: POST
    headers:
      Authorization: !secret marusya_bearer   # в secrets.yaml: marusya_bearer: "Bearer <токен>"
    content_type: application/json
    payload: '{"text": {{ text | to_json }}, "source": "homeassistant"}'
    timeout: 60
  marusya_ask:
    url: http://192.168.31.80:8080/v1/ask
    method: POST
    headers:
      Authorization: !secret marusya_bearer
    content_type: application/json
    payload: '{"text": {{ text | to_json }}, "listen": true, "timeout": 120, "source": "homeassistant"}'
    timeout: 150
```

Пример автоматизации с вопросом:

```yaml
actions:
  - action: rest_command.marusya_ask
    data:
      text: "Стирка закончилась. Включить сушилку?"
    response_variable: r
  - if: "{{ r.status == 200 and r.content.answered and 'да' in r.content.answer | lower }}"
    then:
      - action: switch.turn_on
        target: { entity_id: switch.dryer }
```

## Протокол

WebSocket `GET /v1/stream`, авторизация `Authorization: Bearer <token>`.
Текстовые кадры содержат JSON `models.Message`, бинарные кадры содержат PCM. Полное описание
находится в [internal/models/doc.go](internal/models/doc.go).

| Тип | Направление | Смысл |
|---|---|---|
| `hello` / `ready` | → / ← | рукопожатие, формат аудио, список возможностей устройства |
| `turn_start` / `turn_end` / `turn_cancel` | → | границы реплики пользователя |
| `transcript` | ← | распознанный текст пользователя и текст ответа |
| `command` / `command_result` | ← / → | вызов функции модели и результат |
| `interrupted` / `turn_complete` | ← | ответ прерван / завершён |
| `error` | ← | ошибка |

Модели передаются только инструменты, которые устройство объявило в `hello.capabilities`.
